# SMSBoom

SMSBoom is a Python command-line tool that sends repeated requests to a large list of third-party web and app endpoints that send SMS verification codes. It can run requests concurrently with a thread pool or asyncio, optionally route requests through HTTP, SOCKS5, or SOCKS4 proxies, and can refresh its endpoint lists from a remote URL.

The project's own descriptions (in Chinese) call it an SMS stress-testing tool (`短信测压主程序`) and an SMS bombing tool (`短信轰炸机`).

## Disclaimer

Sending SMS messages or verification-code requests to a phone number without the owner's consent can constitute harassment and may be illegal where you live. Use this software only:

- against phone numbers you own or have explicit permission to test with, and
- against services and systems you are authorized to test.

## Features

- **Multiple request modes** (see [Commands](#commands)):
  - `run`: a thread pool (default 64 workers) that sends requests in repeated waves with a configurable interval.
  - `asyncRun`: sends all requests concurrently with `asyncio` and `httpx.AsyncClient`.
  - `oneRun`: sends requests one at a time in a single thread, for testing.
- **Two endpoint formats**:
  - `api.json`: structured definitions with a description, URL, HTTP method, optional headers, and optional body. Strings containing `[phone]` are replaced with the phone number, and `[timestamp]` is replaced with the current Unix timestamp.
  - `GETAPI.json`: a list of plain GET URLs with `[phone]` placeholders.
- **Proxy support** (`-e` / `--enable_proxy`): reads proxies from `http_proxy.txt`, `socks5_proxy.txt`, and `socks4_proxy.txt`.
- **Endpoint updates**: the `update` command downloads `api.json` and `GETAPI.json` from a remote URL.
- **Logging** to the terminal with [loguru](https://github.com/Delgan/loguru).
- A **Tkinter GUI** (`smsboom_GUI.py`) that is only a partial skeleton; see [Known limitations](#known-limitations).

## Requirements

- Python 3. The repository does not declare a supported Python version. The Dockerfile uses Python 3.9.
- Runtime dependencies in `requirements.txt`:
  - `click==8.1.2`
  - `httpx==0.22.0`
  - `loguru==0.6.0`
  - `pydantic==1.9.0`
  - plus their transitive dependencies (`anyio`, `httpcore`, `h11`, `rfc3986`, and others).
- Tkinter, for the GUI only. It is included with most Python installers, but on some Linux distributions it must be installed separately.

## Installation

```bash
git clone <repository-url> SMSBoom
cd SMSBoom
python -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

`requirements.txt` begins with `-i https://pypi.doubanio.com/simple/`, so pip installs from that package index mirror. Remove that line if you want the default PyPI index.

SOCKS proxies (`socks5_proxy.txt`, `socks4_proxy.txt`) require httpx's SOCKS support, which is not listed in `requirements.txt`. If you use them, install the extra package (for example, `pip install "httpx[socks]==0.22.0"`). This is an unverified note based on how httpx handles SOCKS support, so check it against your environment.

## Usage

Run commands from the repository directory. `smsboom.py` loads `api.json`, `GETAPI.json`, and the proxy files from the directory that contains the script.

Show all commands:

```bash
python smsboom.py --help
```

### Commands

#### `run`

Sends requests in waves. Each wave submits every endpoint to a thread pool, then sleeps for the interval before the next wave.

```bash
python smsboom.py run -p <phone_number> [-t 64] [-f 1] [-i 60] [-e]
```

| Option | Short | Default | Description |
| --- | --- | --- | --- |
| `--phone` | `-p` | prompt | Phone number. Must be digits only. The option can be repeated, but see [Known limitations](#known-limitations). If omitted, the program prompts for it. |
| `--thread` | `-t` | `64` | Number of worker threads. |
| `--frequency` | `-f` | `1` | Number of waves to run. |
| `--interval` | `-i` | `60` | Seconds to wait between waves. |
| `--enable_proxy` | `-e` | off | Use the proxies from the proxy files. Each wave cycles through every proxy. |

Example:

```bash
python smsboom.py run -p <phone_number> -t 16 -f 2 -i 30
```

#### `asyncRun`

Sends all endpoints concurrently with `asyncio`.

```bash
python smsboom.py asyncRun -p <phone_number>
```

Note that this command does not read the `--enable_proxy` setting. It has no proxy option.

#### `oneRun`

Sends requests one at a time. The command is labeled "single thread (for testing)" in its help text.

```bash
python smsboom.py oneRun -p <phone_number>
```

#### `update`

Downloads the latest `api.json` and `GETAPI.json` from a remote mirror and overwrites the local copies.

```bash
python smsboom.py update
```

The download URLs in `smsboom.py` point to a mirror of the GitHub repository `OpenEthan/SMSBoom` on the `master` branch. The command uses a 10-second timeout and disables TLS certificate verification.

If `run` cannot load the endpoint files, it logs an error, runs `update`, and exits. Run the command again after the update finishes.

## Endpoint definitions

### `api.json`

A JSON array of objects. Each object is validated by the `API` model in `utils/models.py`:

```json
{
  "desc": "Example service",
  "url": "https://example.com/api/send_code",
  "method": "POST",
  "header": {"Content-Type": "application/json"},
  "data": {"phone": "[phone]"}
}
```

- `desc`: a label used in log output. Default `"Default"`.
- `url`: required. `[phone]` and `[timestamp]` placeholders are replaced.
- `method`: HTTP method. Default `"GET"`.
- `header`: optional dictionary or string. Defaults to a randomly chosen browser-style `User-Agent`. If no `Referer` header is set, the endpoint's `url` is used as the `Referer`.
- `data`: optional. If it is a dictionary, it is sent as JSON. Otherwise it is sent as form data.

### `GETAPI.json`

A JSON array of strings. Each string is a complete URL. The sender replaces `[phone]` with the phone number and removes spaces and line breaks before sending a GET request.

## Proxies

When `-e` is used, the program reads these files from the script directory:

| File | Format |
| --- | --- |
| `http_proxy.txt` | One `host:port` per line, used as `http://host:port`. |
| `socks5_proxy.txt` | One `host:port` per line, used as `socks5://host:port`. |
| `socks4_proxy.txt` | One `host:port` per line, used as `socks4://host:port`. |

If a file does not exist, the program creates an empty one. If `-e` is used and no proxies are loaded, the program exits with an error.

Without `-e`, requests are sent directly, but the program still reads any proxy files that exist. Each proxy entry then triggers one more full wave of direct requests, so a proxy file with several lines repeats the run that many times.

## Docker

The `Dockerfile` builds an image based on `python:3.9-alpine` and sets `smsboom.py` as the entry point:

```bash
docker build -t smsboom .
docker run -it smsboom run -p <phone_number>
```

This Dockerfile may not build as written. It runs `pipenv install --deploy --ignore-pipfile`, but the repository does not contain a `Pipfile` or `Pipfile.lock`. This README was not checked by building the image.

## GUI

```bash
python smsboom_GUI.py
```

This opens a window titled "SMSBoom - 短信轰炸机" with a phone-number entry and a "启动轰炸" button. The button has no command attached, so the GUI currently does not send any requests.

## Logging

Logs go to standard error at the INFO level. `utils/log.py` creates a `logs/` directory in the current working directory when it is imported, but file logging is commented out, so no log file is written.

## Known limitations

- **Multiple phone numbers do not work as documented.** The `-p` option accepts several numbers, and the loops in `utils/req.py` iterate over them. However, `reqFunc`, `reqFuncByProxy`, and `asyncReqs` `return` inside the first loop iteration, so only the first number is processed for each endpoint.
- **The GUI is incomplete.** The button is not wired to any action.
- **The Dockerfile depends on files that are not in the repository** (`Pipfile` and `Pipfile.lock`), so the image build is likely to fail as written.
- **`debug/` is not documented or tested.** `debug/spider-api.py` imports `Sql` from the `utils` package, but `utils/__init__.py` does not define it. It also uses `requests` and `prettytable`, which are not in `requirements.txt`. These scripts may not run.
- **`utils/sql.py` is not used** by the main program.
- **`asyncRun` and `oneRun` ignore `--enable_proxy`.**
- **TLS verification is disabled** in most request paths (`verify=False`), and the `update` command also disables it.
- **Endpoint lists can go stale.** Many endpoints are old, and some entries have notes in their descriptions, such as "only once per day" or "may only work once." The program does not check whether an endpoint still works.
- **The repository includes no automated tests.**
- **Proxy files are read even without `-e`**, which repeats the direct run once per proxy entry (see [Proxies](#proxies)).

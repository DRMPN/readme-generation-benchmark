# TaskMatrix<h2>Description</h2>

<p>TaskMatrix is an AI assistant project that connects a large language model with a set of specialized tools (including visual foundation models) so that natural-language instructions can be turned into concrete, executable steps.</p>

<p>The system is organized around a few core ideas:</p>

<ul>
<li><p><strong>Planning via a "Planning LLM"</strong> — A dedicated planning component (see the <code>planningLLM</code> class) uses an underlying LLM (accessed through <code>OpenAIWrapper</code>) to decompose a user's request into a strict, step-by-step <strong>Standard Operating Procedure (SOP)</strong>. Each step follows a fixed format:</p>

<p><code>
STEP n: [step name][step description][[[if 'condition'][Jump to STEP m]], ...]
</code></p>

<p>This format allows the plan to include conditional control flow, such as jumping back to a previous step when a condition is not met (e.g., lack of ideas or missing materials).</p></li>
<li><p><strong>SOP refinement and extension</strong> — Because some steps generated by the Planning LLM may be too coarse, the planner can expand a rough step into a detailed sub-SOP (via the extension mechanism). Any sub-SOP must remain consistent with the rest of the plan and must not duplicate content already covered by the original steps.</p></li>
<li><p><strong>Visual capabilities through Visual ChatGPT</strong> — The project integrates Visual ChatGPT, which is designed to assist with a wide range of text and visual tasks: answering questions, generating human-like text, and engaging in natural-sounding, coherent conversations across visual and textual topics.</p></li>
<li><p><strong>Strict output formatting</strong> — The Planning LLM is constrained to respond only in the standard SOP format, with no extra text, so that downstream execution components can reliably parse and follow the plan.</p></li>
</ul>

<p>In short, TaskMatrix acts as a bridge: it takes a high-level user goal, produces a machine-readable plan of named steps with conditions, and carries out those steps using the LLM and attached tools (including the visual models wrapped by Visual ChatGPT).</p>
<h2>Requirements</h2>

<p>To run TaskMatrix, you will need the following:</p>

<ul>
<li><p><strong>Python</strong>: Python 3.7 or higher is required. It is recommended to use Python 3.8+ for best compatibility.</p></li>
<li><p><strong>OpenAI API Key</strong>: The project relies on OpenAI's models (accessed via the <code>OpenAIWrapper</code> used in components such as the Planning LLM) to perform task planning and reasoning. You will need a valid OpenAI API key to use this project. Please set your API key as an environment variable or in the appropriate configuration file before running the project.</p></li>
<li><p><strong>Python Dependencies</strong>: The required Python packages are listed in the <code>requirements.txt</code> file at the root of the repository. You can install them by running:</p></li>
</ul>

<p><code>bash
pip install -r requirements.txt
</code></p>

<ul>
<li><strong>Operating System</strong>: The project is developed and tested on standard development environments (Linux, macOS, Windows).</li>
</ul>

<p>Please make sure all the above requirements are satisfied before proceeding to the installation and usage instructions.</p>
<h2>Installation</h2>

<p>This section describes how to set up the TaskMatrix backend service locally. The project ships with a <code>Dockerfile</code> and a <code>requirements.txt</code> (located in the <code>src/</code> directory), so you can either install the dependencies directly or run the service in a Docker container.</p>

<h3>Prerequisites</h3>

<p>The Docker image used by the project is based on <strong>Ubuntu 22.04</strong> and requires the following system packages:</p>

<ul>
<li><code>git</code></li>
<li><code>python3.11</code></li>
<li><code>python3-pip</code></li>
<li><code>supervisor</code></li>
</ul>

<h3>Option 1: Install dependencies manually</h3>

<ol>
<li><p>Clone the repository:</p>

<p><code>bash
git clone &lt;repository-url&gt;
cd TaskMatrix
</code></p></li>
<li><p>Upgrade <code>pip</code> and <code>setuptools</code>:</p>

<p><code>bash
pip3 install --upgrade pip
pip3 install --upgrade setuptools
</code></p></li>
<li><p>Install the Python dependencies listed in <code>src/requirements.txt</code>:</p>

<p><code>bash
pip3 install -r src/requirements.txt
</code></p>

<p>The main Python dependencies are:</p>

<ul>
<li><code>Flask==2.2.5</code></li>
<li><code>Flask_Cors==3.0.10</code></li>
<li><code>openai==0.27.2</code></li>
<li><code>gunicorn==20.1.0</code></li>
<li><code>gevent==21.8.0</code></li>
</ul></li>
</ol>

<h3>Option 2: Run with Docker</h3>

<p>The repository includes a <code>Dockerfile</code> that builds an image with all system and Python dependencies pre-installed, copies the <code>src/</code> directory into the container, and starts the service via <code>supervisord</code> using the configuration in <code>supervisord.conf</code>:</p>

<p><code>bash
docker build -t taskmatrix .
docker run -p &lt;host-port&gt;:&lt;container-port&gt; taskmatrix
</code></p>

<p>Inside the container, the application code is placed under <code>/app/src</code> and the working directory is set to <code>/app/src</code>. The number of workers is controlled by the <code>WORKERS</code> environment variable (default: <code>2</code>), for example:</p>

<p><code>bash
docker run -e WORKERS=4 -p &lt;host-port&gt;:&lt;container-port&gt; taskmatrix
</code></p>

<blockquote>
  <p><strong>Note:</strong> Since the project depends on the <code>openai</code> package, you may need to configure your OpenAI API credentials before running the service.</p>
</blockquote>
<h2>Usage</h2>

<h3>1. Installation</h3>

<p>Install the required dependencies with pip:</p>

<p><code>bash
pip install -r requirements.txt
</code></p>

<p>The project relies on the following key packages:</p>

<ul>
<li><code>langchain==0.0.101</code></li>
<li><code>torch==1.13.1</code> and <code>torchvision==0.14.1</code></li>
<li><code>openai</code></li>
<li><code>transformers</code>, <code>diffusers</code>, <code>accelerate</code></li>
<li><code>gradio</code> (for the web UI)</li>
<li>Additional libraries such as <code>opencv-python</code>, <code>controlnet-aux</code>, <code>omegaconf</code>, <code>safetensors</code>, and others (see <code>requirements.txt</code> for the full list)</li>
</ul>

<h3>2. Configuration</h3>

<p>The system uses OpenAI's models as the foundation for both the planning component and the task execution. Before running anything, make sure your OpenAI API key is available in the environment:</p>

<p><code>bash
export OPENAI_API_KEY="sk-..."
</code></p>

<h3>3. Planning (Standard Operating Procedure generation)</h3>

<p>The Planning LLM breaks a difficult task down into a standard operating procedure (SOP). The output follows a strict format so it can be executed step by step, including conditional jumps for undetermined situations:</p>

<p><code>
'''
STEP 1: [step name][step descriptions][[[if 'condition1'][Jump to STEP x]], ...]
STEP 2: [step name][step descriptions][[[lack of ideas][Jump to STEP 1]]]
...
'''
</code></p>

<p>If some steps of the SOP are too rough, the Planning LLM can also extend a given step with a detailed sub-SOP. The sub-SOP must stay consistent with the rest of the overall SOP and must not duplicate content already covered by the original plan.</p>

<h3>4. Running the demo</h3>

<p>Once the dependencies are installed and the API key is configured, launch the Gradio-based interface to interact with the system from your browser.</p>

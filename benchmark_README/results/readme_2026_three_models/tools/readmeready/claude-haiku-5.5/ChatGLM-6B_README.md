# ChatGLM-6B<h2>Description</h2>

<p>This section describes the data-related settings used when fine-tuning ChatGLM-6B on a custom dataset. They are defined as dataclass fields with help text, so they can be passed as command-line options to the training script.</p>

<p>The settings cover:</p>

<ul>
<li><strong>Dataset source:</strong> <code>dataset_name</code> and <code>dataset_config_name</code> select a dataset to load through the <code>datasets</code> library. <code>train_file</code>, <code>validation_file</code>, and <code>test_file</code> point to local data files in JSON Lines or CSV format.</li>
<li><strong>Data columns:</strong> <code>prompt_column</code> and <code>response_column</code> name the input and target columns. <code>history_column</code> names the column that holds the chat history.</li>
<li><strong>Sequence lengths:</strong> <code>max_source_length</code> (default 1024) and <code>max_target_length</code> (default 128) cap the tokenized input and target lengths. Longer sequences are truncated, and shorter ones are padded. <code>val_max_target_length</code> sets a separate target limit for validation and defaults to <code>max_target_length</code>.</li>
<li><strong>Preprocessing:</strong> <code>preprocessing_num_workers</code> sets the number of processes used for preprocessing. <code>overwrite_cache</code> rebuilds the cached training and evaluation sets instead of reusing them.</li>
<li><strong>Loss and prompting:</strong> <code>ignore_pad_token_for_loss</code> (default <code>True</code>) excludes padded label tokens from the loss. <code>source_prefix</code> adds a fixed string before every source text.</li>
</ul>

<h2>Usage</h2>

<p>The fine-tuning script takes its options as command-line arguments, defined as dataclass fields. The fields below control which data is loaded and how the model is set up. Defaults are shown where the code defines them.</p>

<h3>Data arguments</h3>

<ul>
<li><strong><code>dataset_name</code></strong> (default: <code>None</code>): The name of the dataset to use, loaded via the Hugging Face <code>datasets</code> library.</li>
<li><strong><code>dataset_config_name</code></strong> (default: <code>None</code>): The configuration name of the dataset to use.</li>
<li><strong><code>train_file</code></strong> (default: <code>None</code>): The input training data file, as a JSON Lines or CSV file.</li>
<li><strong><code>validation_file</code></strong> (default: <code>None</code>): An optional evaluation data file, as a JSON Lines or CSV file, used to compute ROUGE metrics.</li>
<li><strong><code>test_file</code></strong> (default: <code>None</code>): An optional test data file, as a JSON Lines or CSV file, used to compute ROUGE metrics.</li>
<li><strong><code>prompt_column</code></strong> (default: <code>None</code>): The name of the column containing the full input texts.</li>
<li><strong><code>response_column</code></strong> (default: <code>None</code>): The name of the column containing the target responses (summaries).</li>
<li><strong><code>history_column</code></strong> (default: <code>None</code>): The name of the column containing the chat history.</li>
<li><strong><code>overwrite_cache</code></strong> (default: <code>False</code>): Overwrites the cached training and evaluation sets.</li>
<li><strong><code>preprocessing_num_workers</code></strong> (default: <code>None</code>): The number of processes to use for preprocessing.</li>
<li><strong><code>max_source_length</code></strong> (default: <code>1024</code>): The maximum source sequence length.</li>
</ul>

<h3>Model arguments</h3>

<ul>
<li><strong><code>model_revision</code></strong> (default: <code>"main"</code>): The specific model version to use. This can be a branch name, a tag name, or a commit ID.</li>
<li><strong><code>use_auth_token</code></strong> (default: <code>False</code>): When enabled, uses the token generated by <code>huggingface-cli login</code>. This is needed for private models.</li>
<li><strong><code>resize_position_embeddings</code></strong> (default: <code>None</code>): Whether to automatically resize the position embeddings if <code>max_source_length</code> exceeds the model's position embeddings.</li>
<li><strong><code>quantization_bit</code></strong> (default: <code>None</code>)</li>
<li><strong><code>pre_seq_len</code></strong> (default: <code>None</code>)</li>
<li><strong><code>prefix_projection</code></strong> (default: <code>False</code>)</li>
</ul>

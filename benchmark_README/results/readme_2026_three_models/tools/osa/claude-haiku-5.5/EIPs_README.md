## Overview

This repository is a collection of Ethereum Improvement Proposals (EIPs), the design documents that describe proposed changes, standards, and processes for the Ethereum network. It is published as a documentation site at eips.ethereum.org. Each EIP is maintained as a standalone Markdown document with structured metadata at the top of the file, and related proposals reference one another through cross-links, so readers can follow a proposal's status, scope, and rationale. The primary audience is Ethereum protocol and client developers, EIP authors, and researchers, with end users affected indirectly through the standards that result. To understand the proposal process, start with the process-defining EIP, and for contribution guidance, see the Getting Started and Contributing sections.

---

## Core Features

- **Standardized EIP documents:** Hundreds of EIPs are maintained as individual Markdown files with consistent YAML front matter, giving developers a uniform way to find each proposal's status, type, and category.
- **Structured proposal process:** EIP-1 defines the three EIP types (Standards Track, Meta, and Informational), the EIP workflow, and the requirements a proposal must meet, so contributors know how to propose and advance changes.
- **Cross-referenced specifications:** EIPs link to one another through relative references, letting implementers follow dependencies between related standards, such as a transaction type that builds on prior EIPs.
- **Detailed protocol specifications:** Core EIPs such as EIP-1559 include full specifications, reference code, and rationale, giving client and protocol developers the detail needed to implement changes.
- **Contribution guidance:** Contributor aids, including a CONTRIBUTING guide that points to EIP-1 and issue and pull request templates, help authors submit new or updated proposals in the expected format.

## Getting Started

**Prerequisites**

This repository is a collection of Markdown documents. The provided context does not show build, install, or test commands, so no runtime setup is documented here.

**Steps**

1. Get a local copy of the repository. The clone URL is not in the provided context, so use the clone option on the repository's hosting page.
2. Open the `EIPS/` directory. Each EIP is a standalone Markdown file (for example, `EIPS/eip-1.md`).
3. Read `EIPS/eip-1.md` for the EIP purpose, types, and workflow.
4. Review the YAML front matter at the top of any EIP file. The fields include `eip`, `title`, `status`, `type`, `category`, and `created`.
5. Before creating an issue or pull request, read `.github/CONTRIBUTING.md`, which directs contributors to EIP-1 for guidelines.

For installation details beyond these steps, see the Installation section, if one is present.

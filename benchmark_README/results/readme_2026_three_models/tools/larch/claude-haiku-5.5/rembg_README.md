# rembg-74iitifb

A Python tool and library for removing image backgrounds. It wraps a collection of pretrained salient-object-segmentation models, exposes them through a command-line interface, a Python API, and an HTTP server, and ships with Docker and Windows packaging support.

## Overview

`rembg` takes an input image, runs it through a segmentation neural network, and produces an output image in which the background has been removed. The result is a PNG with an alpha (transparency) channel, a binary mask, or a composite over a solid background color.

The project is built on [ONNX Runtime](https://onnxruntime.ai/), so inference runs on CPU by default and can use GPU execution providers (CUDA, TensorRT, DirectML, and others) when available. Model weights are downloaded automatically the first time each model is used.

---

## Features

- **Multiple pretrained models** for general objects, humans, clothing, anime characters, portraits, and high-resolution or dichotomous segmentation tasks.
- **Command-line interface** for single files, whole directories, and binary streams.
- **Python library API** that returns `bytes`, `PIL.Image`, or `numpy.ndarray` depending on input.
- **Built-in HTTP server** with a REST endpoint for background removal.
- **Model reuse via sessions**, so models are loaded once and reused across many images.
- **Alpha matting** for cleaner edges on hair, fur, and fine details.
- **Mask-only output** for producing segmentation masks directly.
- **Mask post-processing** and optional solid background colors.
- **Docker images** for CPU and NVIDIA GPU deployments.
- **Windows installer and executable** build scripts (Inno Setup and PyInstaller).
- **Versioning** managed by `versioneer`, so the version is derived from Git tags.

## Installation

### Requirements

- Python 3.8 or newer (check `pyproject.toml` for the exact supported range)
- pip
- Around 200 MB to several GB of disk space for model weights, depending on which models you use

### Install from PyPI

The CLI and the server require extra dependencies, so install the `cli` extra along with a runtime extra:

```bash
# CPU inference with CLI support
pip install "rembg[cpu,cli]"

# GPU inference (NVIDIA CUDA) with CLI support
pip install "rembg[gpu,cli]"

# Library use only, CPU
pip install "rembg[cpu]"
```

Other useful extras include `rembg[cli]` for the command-line tools alone.

### Install from Source

```bash
git clone <this-repository-url> rembg-74iitifb
cd rembg-74iitifb
pip install -e ".[cpu,cli]"
```

Because the version is derived by `versioneer` from Git metadata, make sure the repository includes its Git history (or tags) when installing from source; otherwise the version may appear as `0+unknown`.

### Choosing the Right ONNX Runtime Package

ONNX Runtime ships separate wheels for CPU, GPU, and specific accelerators. Mixing them up is the most common source of installation problems. See `onnxruntime-installation-matrix.png` in the repository root for a visual guide. In short:

| Hardware | Package |
|---|---|
| CPU only | `onnxruntime` |
| NVIDIA GPU (CUDA) | `onnxruntime-gpu` |
| Windows with DirectML | `onnxruntime-directml` |
| Apple Silicon | `onnxruntime` (CoreML provider available) |

Only one of these should be installed in a given environment. If you switch between them, uninstall the others first:

```bash
pip uninstall -y onnxruntime onnxruntime-gpu onnxruntime-directml
pip install onnxruntime-gpu
```

## Quick Start

### Command Line

```bash
# Remove the background from a single image
rembg i input.jpg output.png

# Process every image in a folder
rembg p input_folder/ output_folder/

# Start the HTTP server
rembg s --host 0.0.0.0 --port 7000
```

### Python

```python
from rembg import remove
from PIL import Image

input_image = Image.open("input.jpg")
output_image = remove(input_image)
output_image.save("output.png")
```

## Command-Line Interface

The CLI is organized into subcommands. Run `rembg --help` or `rembg <command> --help` for the full list of options for your installed version.

| Command | Purpose |
|---|---|
| `rembg i` | Process a single input image |
| `rembg p` | Process all images in a directory |
| `rembg b` | Process binary data from stdin and write to stdout |
| `rembg s` | Start the HTTP server |
| `rembg d` | Download one or more model files ahead of time |

### `rembg i`: Single Image

```bash
rembg i [OPTIONS] INPUT OUTPUT
```

Examples:

```bash
# Default model (u2net)
rembg i photo.jpg photo_nobg.png

# Choose a model
rembg i -m birefnet-general photo.jpg photo_nobg.png

# Enable alpha matting for better edges
rembg i -a photo.jpg photo_nobg.png

# Output only the mask
rembg i -om photo.jpg mask.png
```

### `rembg p`: Directory

```bash
rembg p [OPTIONS] INPUT_DIR OUTPUT_DIR
```

Examples:

```bash
# Process a whole folder with a specific model
rembg p -m isnet-general-use ./photos ./photos_nobg

# Process recursively with a chosen model
rembg p -m u2netp ./dataset ./dataset_out
```

The output filenames follow the input filenames. Results are written with a `.png` extension so transparency is preserved.

### `rembg b`: Binary Stream

Use this command in shell pipelines when you want to pass image bytes through standard input and receive the processed image through standard output:

```bash
cat input.jpg | rembg b > output.png
```

### `rembg s`: HTTP Server

```bash
rembg s --host 0.0.0.0 --port 7000 --log_level info
```

See [HTTP Server](#http-server) for the endpoints.

### `rembg d`: Download Models

```bash
rembg d u2net birefnet-general isnet-general-use
```

Pre-downloading models is useful for offline environments and for Docker builds, where you want model weights baked into the image.

### Common Options

| Option | Description |
|---|---|
| `-m, --model` | Model name to use (default: `u2net`) |
| `-a, --alpha-matting` | Refine edges using alpha matting |
| `-af, --alpha-matting-foreground-threshold` | Foreground threshold for alpha matting |
| `-ab, --alpha-matting-background-threshold` | Background threshold for alpha matting |
| `-ae, --alpha-matting-erode-size` | Erosion size for alpha matting |
| `-om, --only-mask` | Output only the segmentation mask |
| `-ppm, --post-process-mask` | Apply additional smoothing to the mask |
| `-bgc, --bgcolor` | Composite the result over a solid color (for example `255,255,255,255`) |
| `-x, --extras` | Pass model-specific extra options as JSON |

Run `rembg i --help` to confirm the exact spellings for your version.

## Python API

### Basic Usage

```python
from rembg import remove
from PIL import Image

img = Image.open("input.png")
out = remove(img)
out.save("output.png")
```

### Working With Bytes

```python
from rembg import remove

with open("input.png", "rb") as f:
    data = f.read()

result_bytes = remove(data)

with open("output.png", "wb") as f:
    f.write(result_bytes)
```

### Working With NumPy Arrays

```python
import numpy as np
from PIL import Image
from rembg import remove

arr = np.array(Image.open("input.png"))
result = remove(arr)  # returns a numpy array with an alpha channel
```

The return type matches the input type: bytes in, bytes out; PIL in, PIL out; NumPy in, NumPy out.

### Reusing a Model Session

Loading a model is the expensive part. Create a session once and pass it to every call when processing many images:

```python
from rembg import remove, new_session
from pathlib import Path

session = new_session("isnet-general-use")

for path in Path("photos").glob("*.jpg"):
    out = remove(path.read_bytes(), session=session)
    Path("out", path.stem + ".png").write_bytes(out)
```

### Mask Only and Alpha Matting

```python
from rembg import remove

mask = remove(data, only_mask=True)
refined = remove(data, alpha_matting=True)
```

### Parameter Reference

| Parameter | Type | Default | Meaning |
|---|---|---|---|
| `data` | bytes, PIL.Image, or ndarray | required | Input image |
| `session` | session object or `None` | `None` | Reusable model session; defaults to `u2net` if omitted |
| `alpha_matting` | bool | `False` | Refine edges |
| `alpha_matting_foreground_threshold` | int | 240 | Foreground threshold for matting |
| `alpha_matting_background_threshold` | int | 10 | Background threshold for matting |
| `alpha_matting_erode_size` | int | 10 | Erosion size for matting |
| `only_mask` | bool | `False` | Return only the mask |
| `post_process_mask` | bool | `False` | Smooth the mask |
| `bgcolor` | tuple or `None` | `None` | Solid background color, RGBA |

Parameter names can vary slightly between versions; check the docstring of `rembg.bg.remove` in your installed version.

## HTTP Server

Start the server:

```bash
rembg s --host 0.0.0.0 --port 7000
```

The server exposes a Swagger UI at `http://localhost:7000/api` once running.

### Example Request

```bash
curl -X POST "http://localhost:7000/api/remove" \
     -F "file=@input.jpg" \
     -o output.png
```

To choose a model with the server, pass the model parameter in the request as documented in the Swagger UI for your version.

For production, place the server behind a reverse proxy, limit upload sizes, and run it with a process manager. The built-in server is intended for development and internal use.

## Models

The following models are available. The name in the second column is what you pass to `-m` or `new_session()`.

| Model | Name | Best For |
|---|---|---|
| U²-Net | `u2net` | General purpose; default model |
| U²-Net (small) | `u2netp` | Fast, low memory usage |
| U²-Net human segmentation | `u2net_human_seg` | People |
| U²-Net cloth segmentation | `u2net_cloth_seg` | Clothing and garments |
| Silueta | `silueta` | Compact general-purpose model |
| IS-Net general | `isnet-general-use` | General objects with sharp edges |
| IS-Net anime | `isnet-anime` | Anime and illustrated characters |
| Segment Anything (SAM) | `sam` | Prompt-driven segmentation |
| BiRefNet general | `birefnet-general` | High-quality general segmentation |
| BiRefNet general (lite) | `birefnet-general-lite` | Faster BiRefNet variant |
| BiRefNet portrait | `birefnet-portrait` | Portraits and headshots |
| BiRefNet DIS | `birefnet-dis` | Dichotomous image segmentation |
| BiRefNet HRSOD | `birefnet-hrsod` | High-resolution salient object detection |
| BiRefNet COD | `birefnet-cod` | Camouflaged object detection |
| BiRefNet massive | `birefnet-massive` | Trained on a large, diverse dataset |
| BRIA RMBG | `bria-rmbg` | Commercial-oriented general removal |
| BEN | `ben_custom` | Custom BEN model support |
| DIS general use | `dis_general_use` | Dichotomous segmentation, general |
| DIS anime | `dis_anime` | Dichotomous segmentation, anime |

Model names are resolved by `rembg/sessions/session_factory.py`. Models are downloaded on first use into the directory configured by the `U2NET_HOME` environment variable, which defaults to `~/.u2net`.

```bash
export U2NET_HOME=/path/to/models
```

Some models are subject to their own licenses, which may differ from this project's MIT license. Check the upstream model repositories before using a model commercially.

## Choosing a Model

- **Start with `u2net` or `isnet-general-use`** for everyday objects.
- **Use `birefnet-general`** when you need the best quality and have a GPU or can tolerate slower inference.
- **Use `birefnet-general-lite`** for a good balance of speed and quality on CPU.
- **Use `u2net_human_seg` or `birefnet-portrait`** for people and portraits.
- **Use `isnet-anime` or `dis_anime`** for drawings and anime characters.
- **Use `u2net_cloth_seg`** when you specifically need garments separated from the body.
- **Use `u2netp` or `silueta`** on memory-constrained devices.
- **Enable alpha matting** (`-a`) for hair, fur, or semi-transparent edges, at the cost of extra processing time.

## GPU Acceleration

1. Install the NVIDIA driver and CUDA/cuDNN versions compatible with your `onnxruntime-gpu` release.
2. Install the GPU package:

   ```bash
   pip install "rembg[gpu,cli]"
   ```

3. Verify that ONNX Runtime sees the GPU:

   ```python
   import onnxruntime as ort
   print(ort.get_available_providers())
   # Expect 'CUDAExecutionProvider' in the list
   ```

If the CUDA provider is missing, ONNX Runtime silently falls back to CPU, which is slower but still correct. Confirm the provider list whenever performance seems lower than expected.

## Docker

Two Dockerfiles are provided:

| File | Target |
|---|---|
| `Dockerfile` | CPU-only image |
| `Dockerfile_nvidia_cuda_cudnn_gpu` | NVIDIA GPU image with CUDA and cuDNN |

### Build

```bash
# CPU
docker build -f Dockerfile -t rembg:cpu .

# GPU
docker build -f Dockerfile_nvidia_cuda_cudnn_gpu -t rembg:gpu .
```

### Run

```bash
# CPU, start the server on port 7000
docker run --rm -p 7000:7000 rembg:cpu rembg s --host 0.0.0.0 --port 7000

# GPU
docker run --rm --gpus all -p 7000:7000 rembg:gpu rembg s --host 0.0.0.0 --port 7000

# Process a local folder
docker run --rm -v "$PWD/data:/data" rembg:cpu rembg p /data/in /data/out
```

### Docker Compose

`docker-compose.yml` defines the service configuration:

```bash
docker compose up --build
```

To persist downloaded model weights between container runs, mount a volume at the `U2NET_HOME` path inside the container.

## Windows Packaging

The repository includes tooling for producing a standalone Windows distribution:

- **`_build-exe.ps1`**: PowerShell script that builds a single-file executable (typically with PyInstaller).
- **`_setup.iss`**: Inno Setup script that packages the application into a Windows installer.

```powershell

```

Then open `_setup.iss` in Inno Setup Compiler and build the installer. Review the scripts before running them, since paths and versions may need adjustment for your environment.

1. Create a new module in `rembg/sessions/` that subclasses `BaseSession` from `base.py`.
2. Implement the preprocessing, inference, and postprocessing steps for the model's input and output format.
3. Register the model name in `session_factory.py`.
4. Add the model's download URL and checksum where the other models are defined.
5. Add a test case in `test_remove.py` and generate sample outputs for comparison.

## Troubleshooting

**Model download fails or is slow.** Download models ahead of time with `rembg d <model>`, or set `U2NET_HOME` to a directory with pre-downloaded files.

**`onnxruntime` errors or conflicts.** Multiple ONNX Runtime packages are installed. Uninstall all of them and install only the one matching your hardware (see [Choosing the Right ONNX Runtime Package](#choosing-the-right-onnxruntime-package)).

**GPU is not used.** Check `onnxruntime.get_available_providers()`. Make sure the CUDA and cuDNN versions match what `onnxruntime-gpu` requires.

**Out of memory.** Use a smaller model such as `u2netp` or `birefnet-general-lite`, downscale the input image, or disable alpha matting.

**Edges look rough.** Enable alpha matting (`-a`) or try `isnet-general-use` or `birefnet-general`.

**Version shows as `0+unknown`.** The repository was installed without Git metadata. Clone with full history or fetch tags.

**Windows `.exe` fails to start.** Make sure the build included all model dependencies and that antivirus software has not quarantined the executable.

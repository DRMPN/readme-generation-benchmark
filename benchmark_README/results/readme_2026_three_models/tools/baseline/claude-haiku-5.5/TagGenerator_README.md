# TagGenerator

TagGenerator is a reusable Django app, packaged as `QrCode`, that generates styled QR code images. It also includes a sample Django project, `TagGenerator`, that wires the app into a working site with a simple HTML front end.

## Overview

The project provides:

- **A QR code image endpoint** that returns a PNG for any text passed in the `data` query parameter.
- **A home page** (a template named `qr_code_frontend.html`) with a form titled "QR Code Generator".
- **A `QRCode` model** with `data` and `created` fields, registered in the Django admin.
- **A template tag**, `qrcode_url`, for building QR code image URLs inside Django templates.
- **Docker and GitHub Actions support** for testing, container image publishing, and PyPI packaging.

The QR codes use the `qrcode` library with `StyledPilImage`, a rounded module drawer, and a radial gradient color mask. Each code is generated with high error correction (`ERROR_CORRECT_H`), a box size of 10, and a border of 4.

## Requirements

- Python 3.9 or later (`setup.py` sets `python_requires=">=3.9"`).
- Django 4.0 or later (`setup.py` requires `Django>=4.0`; the sample project's settings were generated by Django 5.1.7).
- `qrcode` and `Pillow`, which are listed in `setup.py`.

The full dependency list is in `requirements.txt`, which the Dockerfile and CI workflow install.

## Setup

### Local installation

1. Clone the repository:

   ```bash
   git clone https://github.com/DadaNanjesha/TagGenerator.git
   cd TagGenerator
   ```

2. Create and activate a virtual environment:

   ```bash
   python -m venv venv
   source venv/bin/activate        # On Windows: venv\Scripts\activate
   ```

3. Install the dependencies:

   ```bash
   pip install -r requirements.txt
   ```

4. Apply the database migrations. The sample project uses SQLite, stored at `db.sqlite3` in the project root:

   ```bash
   python manage.py migrate
   ```

5. Optionally, create an admin user to access the Django admin:

   ```bash
   python manage.py createsuperuser
   ```

### Docker

The `Dockerfile` uses `python:3.9-slim-buster`, copies the project into `/app`, installs `libpq-dev`, installs the packages in `requirements.txt`, and exposes port 8000.

Build and run the image:

```bash
docker build -t taggenerator .
docker run -p 8000:8000 taggenerator
```

The container starts with `python manage.py runserver 0.0.0.0:8000`. The Dockerfile does not run `migrate`, so you may need to run it inside the container before using the admin:

```bash
docker run -it -p 8000:8000 taggenerator python manage.py migrate
```

A prebuilt image is published to GitHub Container Registry by the publishing workflow (see [Continuous Integration and Publishing](#continuous-integration-and-publishing)).

## Usage

### Running the development server

```bash
python manage.py runserver
```

Then open the following URLs:

| URL | Description |
|-----|-------------|
| `http://127.0.0.1:8000/qrcode/` | Home page with the QR Code Generator form |
| `http://127.0.0.1:8000/qrcode/generate/?data=<text>` | Returns a PNG QR code for `<text>` |
| `http://127.0.0.1:8000/admin/` | Django admin (requires a superuser) |

If `data` is omitted, the generator encodes the default text `Hello, Beautiful QR Code!`.

Example:

```
http://127.0.0.1:8000/qrcode/generate/?data=https://example.com
```

The response has the content type `image/png`. Query values are URL-encoded, so spaces and special characters should be encoded as usual.

### Using the template tag

To use the `qrcode_url` tag in your own templates, load the tag library and pass the text to encode:

```django
{% load qrcode_tags %}

<img src="{% qrcode_url 'Some text to encode' %}" alt="QR Code">
```

The tag calls `reverse("qrcode:generate")` and appends the URL-encoded `data` parameter, so it returns a URL such as `/qrcode/generate/?data=Some+text+to+encode`.

### Using the QRCode model

The `QRCode` model stores a `data` text field and an automatically set `created` timestamp. Its `__str__` method returns the first 50 characters of `data`. The model is registered in the admin with `data` and `created` shown in the list view.

Note that the image-generation view does not save anything to the database. Records appear in the model only if they are created through the admin or other code.

### Reusing the app in another project

The `QrCode` app can be installed as a package. Add `'QrCode'` to `INSTALLED_APPS`, include its URLs under the `qrcode` namespace, and run migrations:

```python
# urls.py
from django.urls import path, include

urlpatterns = [
    path("qrcode/", include("QrCode.urls", namespace="qrcode")),
]
```

```bash
python manage.py migrate
```

The app's `apps.py` defines `QrcodeConfig` with `name = 'QrCode'`.

## Configuration

Configuration lives in `TagGenerator/settings.py`. The file is marked as a development configuration, and several values should be changed before deployment.

| Setting | Current value | Notes |
|---------|---------------|-------|
| `SECRET_KEY` | Hard-coded string | Should be replaced with a secret value loaded from the environment for any non-development use. |
| `DEBUG` | `True` | Must be set to `False` in production. |
| `ALLOWED_HOSTS` | `[]` | Must list the production hostnames when `DEBUG` is `False`. |
| `DATABASES` | SQLite at `BASE_DIR / 'db.sqlite3'` | Development default. |
| `TEMPLATES[0]['DIRS']` | `BASE_DIR / "templates"` | Enables loading `qr_code_frontend.html` from the top-level `templates/` directory. |
| `TIME_ZONE` | `'UTC'` | |
| `LANGUAGE_CODE` | `'en-us'` | |
| `STATIC_URL` | `'static/'` | |
| `DEFAULT_AUTO_FIELD` | `django.db.models.BigAutoField` | |

The `Dockerfile` runs the development server (`runserver`), not a production WSGI or ASGI server. The `wsgi.py` and `asgi.py` files are provided for deployment with a server of your choice.

To change the default QR code text or appearance, edit `GenerateQRCodeView` in `QrCode/views.py`. The default `data` value, `version`, `box_size`, `border`, module drawer, and color mask are set there.

## Development

1. Install the dependencies as described in [Setup](#setup).
2. Make model changes in `QrCode/models.py`, then generate and apply migrations with Django's standard commands:

   ```bash
   python manage.py makemigrations
   python manage.py migrate
   ```

3. Run the development server with `python manage.py runserver`.

Views live in `QrCode/views.py`, URL patterns in `QrCode/urls.py`, and the template tag in `QrCode/templatetags/qrcode_tags.py`. The HTML template is in `templates/qr_code_frontend.html`.

The repository has `.gitignore` and `.dockerignore` files, which control what is excluded from version control and the Docker build context. Their contents are not described here.

## Testing

Tests are in `QrCode/tests.py` and run with Django's test runner:

```bash
python manage.py test
```

The test suite covers:

- **`GenerateQRCodeViewTest`**
  - Requesting the generate endpoint without `data` returns HTTP 200, a `image/png` content type, and non-empty content.
  - Requesting it with `data=https://example.com` returns the same kind of response.
- **`QRCodeHomeViewTest`**
  - The home page returns HTTP 200 and contains a `<form` element and the text "QR Code Generator".

The GitHub Actions workflow `.github/workflows/django.yml` runs the same command on Ubuntu with Python 3.9.

## Continuous Integration and Publishing

The repository includes three GitHub Actions workflows:

- **Django CI** (`.github/workflows/django.yml`): runs on pushes to `main` and `dev`, and on pull requests targeting `main`. It installs `requirements.txt` on Python 3.9 and runs `python manage.py test`.
- **Publish Docker Image** (`.github/workflows/publish-docker.yml`): runs on pushes to `main`. It logs in to GitHub Container Registry (`ghcr.io`) and builds and pushes the image tagged `ghcr.io/dadananjesha/taggenerator:latest`.
- **Upload Python Package** (`.github/workflows/python-publish.yml`): runs when a release is published. It builds the distribution with `python -m build` and publishes it to PyPI using trusted publishing through the `pypi` environment.

The package metadata in `setup.py` gives the following details:

- Name: `TagGenerator`
- Version: `1.0.2`
- Description: "A reusable Django app for QR Code generation"
- Packages: `QrCode`
- Install requirements: `Django>=4.0`, `qrcode`, `Pillow`

`setup.py` reads this README as the long description, so it is shown on the package index.
